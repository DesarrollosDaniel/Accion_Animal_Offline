Esta guía instala una PC nueva como sustituta de la PC que actualmente ejecuta
Acción Animal Offline. Las operaciones clínicas se almacenan primero en
PostgreSQL local; watch envía únicamente las operaciones explícitas de la cola
local a Supabase y recibe los cambios remotos. La ausencia de una fila local
NO produce una eliminación en Supabase. Las eliminaciones hechas expresamente
en la interfaz sí se envían. No enciendas dos instalaciones activas a la vez.

3. CREAR POSTGRESQL LOCAL DE PRODUCCIÓN

En la raíz del repositorio, crea la base vacía. Cada comando psql solicitará
la contraseña del postgres LOCAL, no la de Supabase:

    $psql = 'C:\Program Files\PostgreSQL\18\bin\psql.exe'
    & $psql -X -h 127.0.0.1 -p 5432 -U postgres -d postgres -W -v ON_ERROR_STOP=1 -c 'CREATE DATABASE accion_animal_produ'

Aplica las ocho migraciones EN ORDEN y únicamente sobre accion_animal_produ:

    & $psql -X -h 127.0.0.1 -p 5432 -U postgres -d accion_animal_produ -W -v ON_ERROR_STOP=1 -f 'db/local/migrations/001_initial_schema.sql' -f 'db/local/migrations/002_sync_foundation.sql' -f 'db/local/migrations/003_offline_auth.sql' -f 'db/local/migrations/004_pet_inbound.sql' -f 'db/local/migrations/005_clinical_records_inbound.sql' -f 'db/local/migrations/006_clinical_resources_inbound.sql' -f 'db/local/migrations/007_incremental_inbound.sql' -f 'db/local/migrations/008_multiple_owners.sql'

Detente si psql muestra ERROR o devuelve un código distinto de cero. Las
migraciones no deben repetirse sobre una base ya preparada. La 008 permite
los dos perfiles owner que existen en este proyecto de producción.

La migración 002 creó aa_local_app SIN LOGIN. Asígnale una contraseña nueva:

    & $psql -X -h 127.0.0.1 -p 5432 -U postgres -d accion_animal_produ -W

DENTRO de psql, escribe las siguientes líneas por separado. Después de
\password introduce dos veces la nueva clave de aa_local_app cuando la pida:

    \password aa_local_app
    ALTER ROLE aa_local_app LOGIN;
    \q

Comprueba que aparezca ALTER ROLE. No escribas \password en PowerShell.

8. GUARDAR LAS DOS CLAVES DE EJECUCIÓN AUTOMÁTICA PARA ESA CUENTA WINDOWS

Las tareas de Windows no heredan las variables $env: de tu PowerShell. Usa la
MISMA cuenta Windows con la que ejecutarás las tareas. PowerShell cifra estos
dos archivos con DPAPI para esa cuenta y esa PC; no copies los archivos a otra
cuenta o máquina. En una PowerShell normal de esa cuenta:

    Set-Location C:\AccionAnimal\Accion_Animal_Offline
    $secretDir = Join-Path $env:LOCALAPPDATA 'AccionAnimalOffline'
    New-Item -ItemType Directory -Path $secretDir -Force
    Read-Host 'Contraseña local de aa_local_app' -AsSecureString | ConvertFrom-SecureString | Set-Content -LiteralPath (Join-Path $secretDir 'aa_db_password.dpapi')
    Read-Host 'Contraseña de aa_sync_worker PRODUCCIÓN' -AsSecureString | ConvertFrom-SecureString | Set-Content -LiteralPath (Join-Path $secretDir 'aa_worker_password.dpapi')

No guardes aquí la contraseña postgres de Supabase; solo se necesita para la
importación/diagnóstico administrativo, no para el funcionamiento diario.
Protege la cuenta Windows con contraseña y limita el acceso a esta carpeta.

En la misma PC crea instalacion\iniciar-produccion.ps1 con Bloc de notas y
PEGA EXACTAMENTE el siguiente contenido:

    param([ValidateSet('server','watch')][string]$Mode)
    $ErrorActionPreference = 'Stop'
    $projectRoot = Split-Path -Parent $PSScriptRoot
    $secretDir = Join-Path $env:LOCALAPPDATA 'AccionAnimalOffline'
    $node = Join-Path $env:ProgramFiles 'nodejs\node.exe'
    Set-Location -LiteralPath $projectRoot
    $env:AA_DB_PASSWORD = [System.Net.NetworkCredential]::new('', (Get-Content -LiteralPath (Join-Path $secretDir 'aa_db_password.dpapi') -TotalCount 1 | ConvertTo-SecureString)).Password
    if ($Mode -eq 'watch') {
      $env:AA_PROD_WORKER_PASSWORD = [System.Net.NetworkCredential]::new('', (Get-Content -LiteralPath (Join-Path $secretDir 'aa_worker_password.dpapi') -TotalCount 1 | ConvertTo-SecureString)).Password
    }
    if (-not (Test-Path -LiteralPath $node)) { throw 'No se encontró node.exe' }
    $log = Join-Path $secretDir ("$Mode.log")
    if ($Mode -eq 'server') {
      & $node --env-file=.env.production.local server/local-server.mjs *>> $log
    } else {
      & $node --env-file=.env.production.local scripts/sync-production.mjs --watch *>> $log
    }
    throw "El proceso $Mode terminó con código $LASTEXITCODE. Revisa $log"

Comprueba primero el launcher en PowerShell normal, por separado. Cada uno
queda ejecutándose; usa Ctrl+C para detenerlo. El primero debe servir health;
el segundo debe conectar y dejar «Perfiles de PRODUCCIÓN recibidos» en watch.log:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\instalacion\iniciar-produccion.ps1 server
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\instalacion\iniciar-produccion.ps1 watch

Los registros quedan en %LOCALAPPDATA%\AccionAnimalOffline\server.log y
watch.log. Un error de conexión aparecerá allí. Si cambias cualquiera de las
dos contraseñas, vuelve a generar el archivo .dpapi correspondiente con la
contraseña nueva y reinicia la tarea. No copies estos archivos al repositorio.
Para leer el final de cada registro desde PowerShell:

    Get-Content (Join-Path $env:LOCALAPPDATA 'AccionAnimalOffline\server.log') -Tail 30
    Get-Content (Join-Path $env:LOCALAPPDATA 'AccionAnimalOffline\watch.log') -Tail 30

9. PROGRAMAR EL SERVIDOR Y WATCH AL ENCENDER WINDOWS

Abre Programador de tareas (Win+R, taskschd.msc) y usa «Crear tarea» DOS
veces, nunca «Crear tarea básica». Crea ambas bajo la MISMA cuenta Windows
del paso 8. Esa cuenta necesita contraseña de Windows para poder seleccionar
«Ejecutar tanto si el usuario inició sesión como si no». Deja desmarcada la
opción «No almacenar contraseña» para que DPAPI pueda abrir los secretos.

Tarea 1: Accion Animal Offline - Servidor
  General: ejecutar aunque el usuario no haya iniciado sesión; sin privilegios
           elevados (el uso diario no requiere administrador).
  Desencadenador: al iniciar el sistema; retrasar 1 minuto.
  Acción > Programa: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  Acción > Argumentos:
    -NoProfile -ExecutionPolicy Bypass -File "C:\AccionAnimal\Accion_Animal_Offline\instalacion\iniciar-produccion.ps1" server
  Acción > Iniciar en (SIN comillas):
    C:\AccionAnimal\Accion_Animal_Offline

Tarea 2: Accion Animal Offline - Watch
  General: la misma cuenta y configuración de la tarea 1.
  Desencadenador: al iniciar el sistema; retrasar 2 minutos.
  Acción > Programa: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  Acción > Argumentos:
    -NoProfile -ExecutionPolicy Bypass -File "C:\AccionAnimal\Accion_Animal_Offline\instalacion\iniciar-produccion.ps1" watch
  Acción > Iniciar en (SIN comillas):
    C:\AccionAnimal\Accion_Animal_Offline

En AMBAS tareas, pestaña Condiciones: desmarca «Iniciar solamente si está
conectado a corriente alterna» y «Detener si cambia a batería». En
Configuración: habilita iniciar a petición, reiniciar cada minuto si falla
(al menos 10 intentos), «Si ya se está ejecutando: no iniciar una instancia
nueva», y desmarca «Detener la tarea si dura más de...». Windows solicitará la
contraseña de esa cuenta al guardar. Verifica que el servicio de PostgreSQL
también tenga inicio automático en services.msc.

Usa «Ejecutar» en cada tarea para probar. Comprueba health y los dos logs.
Reinicia Windows y vuelve a comprobar: tarea Servidor en ejecución, tarea
Watch en ejecución, health con database=available y la interfaz accesible.
Un watch estable puede permanecer en silencio si no hay cambios; eso es

10. ACCESO DESDE OTRAS COMPUTADORAS Y VERIFICACIÓN FINAL

En la PC servidor comprueba que la red del consultorio sea Privada:

    Get-NetConnectionProfile

En PowerShell COMO ADMINISTRADOR crea una sola regla para el puerto 4174,
únicamente en redes privadas:

    New-NetFirewallRule -DisplayName 'Accion Animal Offline 4174' -Direction Inbound -Protocol TCP -LocalPort 4174 -Action Allow -Profile Private

Con ipconfig obtén la IPv4 local. Desde otra PC en la misma red abre
http://IP-DE-LA-PC-SERVIDOR:4174. No abras el puerto al internet público ni
configures port forwarding/DMZ en el router. Reserva la IP del servidor en el
router si otras PC lo usarán diariamente. Evita que Windows suspenda esta PC
y confirma que PostgreSQL, servidor Node y watch arranquen tras reiniciar.

Verificación funcional mínima: entra con un usuario activo, busca una mascota
conocida, abre su ficha y comprueba que los datos aparecen. Comprueba que los
archivos físicos que sí copiaste se abran. Un cambio local autorizado debe
quedar confirmed en watch; un cambio remoto nuevo debe llegar a la PC y mover
el cursor. Si hay conflict o blocked, revísalo antes de dar la instalación por
lista. Para diagnóstico sin enviar operaciones, detén primero el watch
programado y ejecuta en PowerShell con sus claves cargadas:

    node --env-file=.env.production.local scripts/sync-production.mjs --check

La tarea Watch se reanuda desde su cursor guardado; no necesita importar todo
otra vez. Para ver también las recepciones pendientes se puede usar
scripts/check-production-sync.mjs, pero requiere AA_PROD_DB_PASSWORD en esa
PowerShell y hace solo lecturas. No uses el importador otra vez sobre una base
que ya recibió datos o cambios locales.
